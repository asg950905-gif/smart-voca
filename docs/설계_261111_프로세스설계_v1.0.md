## 1. 인증 프로세스 (P01, P02)

### P01: 회원가입

**목표**: 새 사용자 계정을 생성하고 데이터 초기화

| 단계 | 설명 | 입력 데이터 | 처리 로직 | 출력 데이터 |
|-----|------|---------|---------|---------|
| 1.1 | 가입 폼 표시 | 요청 (GET) | 가입 폼 렌더링 | HTML 폼 |
| 1.2 | 입력 검증 | `username`, `password`, `password_confirm` | 아이디: 영문·숫자·밑줄 3~20자, 중복 확인<br/>비밀번호: 6자 이상, 일치 확인 | 검증 결과 (성공/실패) |
| 1.3 | 계정 생성 (실패 시 1.4로) | 검증된 `username`, 해시된 `password` | DB 테이블 `users` 에 INSERT<br/>기본값: `role='user'`, `is_active=1`, `created_at=NOW()` | 새 user_id |
| 1.4 | 초기 사용자 데이터 생성 | 생성된 `user_id` | `user_settings` 에 기본값 생성<br/>- `daily_target = 50` (관리자 설정값)<br/>- `theme = 'system'`<br/>- `created_at = NOW()` | 초기화 완료 |
| 1.5 | 성공 응답 | (성공시에만) | 로그인 페이지로 리다이렉트 | HTTP 302 + 메시지 |
| 1.6 | 오류 응답 | (실패시) | 가입 폼으로 돌아감, 오류 메시지 표시 | HTTP 400 + 오류 메시지 |

**관련 요구사항**: FR-101

**알고리즘**: 
```
회원가입(username, password):
```

## 2. 학습 프로세스 (P10)

### P10: 일일 학습

**목표**: 사용자가 매일 설정된 개수만큼 단어를 학습하고, 학습 결과를 기록하며 통계에 반영

| 단계 | 설명 | 입력 데이터 | 처리 로직 | 출력 데이터 |
|-----|------|---------|---------|---------|
| 10.1 | 학습 페이지 진입 | 요청 (GET), `user_id` (세션) | 사용자의 `user_settings.daily_target` 조회 | 오늘의 목표 단어 수 |
| 10.2 | 일일 단어 조회 | `user_id`, `daily_target` | DB 쿼리:<br/>1. `user_word_stats` 의 `weight` 내림차순 (오답 많은 순)<br/>2. 아직 본 적 없는 단어 (가중치=0)<br/>3. 오래전에 본 단어 (마지막 학습일 기준)<br/>4. 무작위<br/>상위 N개 반환 | 단어 목록 (ID, 영단어, 뜻) |
| 10.3 | 학습 UI 표시 | 단어 목록 | 각 단어마다 "외웠음(O)/아직(X)" 버튼 표시<br/>진행 바 표시 | HTML 학습 화면 |
| 10.4 | 사용자 입력 수집 | 사용자 선택 (O/X) | 모든 단어 선택 완료 대기 | 학습 결과 객체 |
| 10.5 | 결과 저장 요청 | `{"results": [{"word_id": int, "is_correct": bool}, ...]}` (POST) | CSRF 토큰 검증 | 검증 결과 |
| 10.6 | 결과 처리 (트랜잭션) | 학습 결과 | **트랜잭션 시작**<br/>1. 각 word_id에 대해:<br/>   - 존재하지 않는 word_id → 무시<br/>   - `user_word_stats` 업데이트:<br/>     - is_correct=True → weight -= 1 (최소 0)<br/>     - is_correct=False → weight += 1<br/>     - last_studied_at = NOW()<br/>   - `study_logs` INSERT: user_id, word_id, is_correct, created_at<br/>2. XP 계산:<br/>   - 정답 +10, 오답 +2<br/>   - 누적 XP 업데이트, 레벨 확인<br/>3. 연속 학습일(streak) 업데이트:<br/>   - 오늘 처음 학습 → streak_count += 1, last_studied_date = TODAY()<br/>   - 어제 이후 미학습 → streak_count 유지 (어제까지의 streak 보존)<br/>**트랜잭션 커밋** | 학습 완료, XP, 레벨 정보 |
| 10.7 | 응답 | (6단계 성공시) | JSON: `{status: "success", xp_gained: int, level: int, level_up: bool, message: "..."}` | HTTP 200 + JSON |

**관련 요구사항**: FR-301, FR-302, FR-303, FR-304, FR-305, FR-601, FR-701

**알고리즘**:
```
일일학습(user_id, results):
  daily_target = DB.user_settings.SELECT daily_target WHERE user_id
  
  1. 일일 단어 가져오기:
    words = DB.user_word_stats
      .SELECT word_id, weight, last_studied_at
      .WHERE user_id = user_id
      .ORDER BY weight DESC, last_studied_at ASC, RANDOM()
      .LIMIT daily_target
  
  2. 결과 저장 (트랜잭션):
    total_xp = 0
    FOR each result in results:
      if result.word_id not in DB.words:
        continue # 무시
      
      weight_change = -1 if result.is_correct else +1
      weight = MAX(0, current_weight + weight_change)
      DB.user_word_stats.UPDATE weight, last_studied_at = NOW()
      DB.study_logs.INSERT user_id, word_id, is_correct
      
      xp_gain = 10 if result.is_correct else 2
      total_xp += xp_gain
    
    3. XP 및 레벨 업데이트:
      new_xp = user.total_xp + total_xp
      new_level = calculate_level(new_xp)
      level_up = (new_level > user.level)
      DB.users.UPDATE total_xp, level
    
    4. 연속 학습일 업데이트:
      if user.last_studied_date != TODAY():
        if user.last_studied_date == YESTERDAY():
          streak_count += 1 # 연속 유지
        else:
          streak_count = 1 # 리셋 (어제 이전에 미학습했으면)
      DB.users.UPDATE streak_count, last_studied_date = TODAY()
  
  COMMIT 트랜잭션
  return {xp_gained: total_xp, level: new_level, level_up, message}
```

## 3. 시험 프로세스 (P20)

### P20: 시험 시작·진행·종료

**목표**: 사용자가 설정한 옵션으로 시험을 풀고, 즉시 채점하며, 결과를 저장

| 단계 | 설명 | 입력 데이터 | 처리 로직 | 출력 데이터 |
|-----|------|---------|---------|---------|
| 20.1 | 시험 설정 폼 표시 | 요청 (GET) | 시험 옵션 폼: 문제 수, 출제 모드, 출제 형식 | HTML 설정 폼 |
| 20.2 | 시험 시작 요청 | `num_problems`, `mode` (한→영/영→한/혼합), `format` (단답/4지선/OX/빈칸/혼합) (POST) | 옵션 유효성 검증<br/>CSRF 토큰 검증 | 검증 결과 |
| 20.3 | 시험 문제 생성 (트랜잭션) | 검증된 옵션 | 1. 문제 수 보정: 1 ~ `global_settings.max_test_problems` (기본 50)<br/>2. 출제 단어 선택:<br/>   - DB `user_word_stats` 에서 weight 내림차순<br/>   - 부족시 형식 낮추기:<br/>     - 4지선다/빈칸/혼합 → 4개 미만이면 OX<br/>     - OX → 2개 미만이면 단답<br/>   - 단어 0개면 시험 불가<br/>3. 시험 세션 생성:<br/>   - DB `test_sessions` INSERT:<br/>     - user_id, status='in_progress'<br/>     - problem_set (JSON): 문제 배열<br/>     - current_index = 0<br/>     - score = 0, correct_count = 0<br/>     - created_at = NOW() | 시험 세션 ID |
| 20.4 | 현재 문제 조회 | 시험 세션 ID (GET) | DB `test_sessions` 에서 현재 문제 인덱스의 문제 반환<br/>정답은 클라이언트로 보내지 않음<br/>문제 형식에 따라 선택지 제시 (단답: 텍스트 입력, 4지선다: 4개 선택지, OX: True/False 등) | 문제 정보 (문제 텍스트, 형식, 선택지, 현재 번호/전체) |
| 20.5 | 답 제출 | 시험 세션 ID, 사용자 답안 (POST) | CSRF 토큰 검증 | 검증 결과 |
| 20.6 | 즉시 채점 | 정답과 사용자 답안 | 문자열 비교:<br/>- 앞뒤 공백 제거<br/>- 대소문자 무시<br/>- 전체 일치만 정답<br/>결과는 즉시 반환 | 정오답 + 정답 |
| 20.7 | 결과 저장 및 다음 문제로 | 채점 결과 | DB 트랜잭션:<br/>1. `test_sessions.problem_set` 에서 현재 문제 결과 업데이트<br/>2. 정답이면 score += (100 / total_problems), correct_count += 1<br/>3. current_index += 1<br/>4. DB 업데이트 | 다음 문제 또는 종료 신호 |
| 20.8 | 시험 종료 | 시험 세션 ID (POST) | 풀이한 문제가 0개면 종료 불가<br/>DB 트랜잭션:<br/>1. 최종 점수 계산 및 저장<br/>2. `test_logs` INSERT: user_id, score, correct_count, created_at<br/>3. 각 문제마다 user_word_stats 업데이트:<br/>   - 정답 → weight -= 1, XP += 15<br/>   - 오답 → weight += 1, XP += 3<br/>4. 사용자 레벨 재계산<br/>5. `test_sessions` 삭제 (또는 status='completed')<br/>COMMIT | 최종 점수, XP 획득, 레벨 정보 |

**관련 요구사항**: FR-401~408, FR-601~603

**알고리즘**:
```
시험시작(num_problems, mode, format):
  num_problems = clamp(num_problems, 1, max_test_problems)
  
  words = DB.user_word_stats.SELECT.WHERE user_id
    .ORDER BY weight DESC
    .LIMIT num_problems
  
  if len(words) == 0:
    return 오류("학습할 단어가 없습니다")
  
  # 형식 검증 및 낮추기
  if format in ['4선다', '빈칸', '혼합'] and len(words) < 4:
    format = 'OX'
  if format == 'OX' and len(words) < 2:
    format = '단답'
  
  problem_set = generate_problems(words, mode, format)
  test_session = DB.test_sessions.INSERT(
    user_id, status='in_progress', problem_set, current_index=0, score=0
  )
  return test_session.id

채점(answer, correct_answer):
  answer_normalized = answer.strip().lower()
  correct_normalized = correct_answer.strip().lower()
  return answer_normalized == correct_normalized

시험종료(test_session_id):
  session = DB.test_sessions.SELECT WHERE id = test_session_id
  if session.current_index == 0:
    return 오류("풀이한 문제가 없습니다")
  
  final_score = (session.correct_count / len(session.problem_set)) * 100
  total_xp = 0
  
  FOR each problem in session.problem_set:
    if problem.is_correct:
      weight_change = -1
      xp_gain = 15
    else:
      weight_change = +1
      xp_gain = 3
    
    DB.user_word_stats.UPDATE weight += weight_change WHERE word_id
    total_xp += xp_gain
  
  DB.test_logs.INSERT user_id, score, correct_count, created_at=NOW()
  new_xp = user.total_xp + total_xp
  new_level = calculate_level(new_xp)
  DB.users.UPDATE total_xp, level
  DB.test_sessions.DELETE WHERE id = test_session_id
  
  COMMIT
  return {score: final_score, xp_gained: total_xp, level: new_level}
```

### P30: 통계 생성·조회·내보내기

| 단계 | 설명 | 입력 데이터 | 처리 로직 | 출력 데이터 |
|-----|------|---------|---------|---------|
| 30.1 | 통계 페이지 진입 | 요청 (GET), `user_id` | 통계 데이터 조회 요청 | 페이지 로드 |
| 30.2 | 요약 통계 생성 | `user_id` | DB 집계 쿼리:<br/>- 학습 일수: COUNT(DISTINCT DATE(created_at)) FROM study_logs<br/>- 학습한 단어: COUNT(DISTINCT word_id) FROM user_word_stats WHERE weight >= 0<br/>- 평균 학습 성공률: AVG(시도별 성공률) FROM study_logs<br/>- 시험 응시 횟수: COUNT(*) FROM test_logs<br/>- 평균/최고 시험 점수: AVG/MAX(score) FROM test_logs<br/>- 오늘 학습 여부: EXISTS(study_logs WHERE DATE(created_at) = TODAY()) | 요약 통계 JSON |

## 7. 프로세스 간 의존성

```
인증 (P01, P02)
  ↓ (로그인 필요)
┌─ 학습 (P10) ─→ 게임화 (P40: XP 획득, 레벨)
│   ↓
│   통계 (P30: 데이터 반영)
│
├─ 시험 (P20) ─→ 게임화 (P40: XP 획득, 레벨)
│   ↓
│   통계 (P30: 데이터 반영)
│
└─ 리그 (P40.3: 주간 리그 조회)

관리자 (P50, P51, P52, P53) ← 별도 권한 확인
  ├─ P50 (단어 CRUD) → 기본 데이터 관리
  ├─ P51 (CSV I/O) → 대량 단어 관리
  ├─ P52 (사용자 관리) → 계정 제어
  └─ P53 (설정 관리) → 시스템 설정
```

## 8. 주요 데이터 흐름

### 학습 → 통계 → 게임화 (순환)
1. 사용자가 단어 학습 (P10)
2. 학습 로그 저장, 단어 통계 업데이트
3. XP 획득 (P40.1), 레벨 계산 (P40.2)
4. 통계 페이지에서 누적 데이터 조회 (P30)
5. 주간 리그에 자동 반영 (P40.3)

### 시험 → 통계 → 게임화 (순환)
1. 사용자가 시험 풀이 (P20)
2. 시험 로그 저장, 단어 통계 업데이트
3. XP 획득 (높은 배율), 레벨 계산
4. 통계 페이지에서 시험 성적 조회 (P30)

### 관리자 → 사용자 데이터 영향
- P50 (단어 CRUD): 모든 사용자의 학습 대상 단어 변경
- P51 (CSV): 대량 단어 추가 후 모든 사용자에게 제시
- P52 (사용자 관리): 계정 활성화 상태 제어
- P53 (설정 관리): 새 사용자의 기본값 또는 모든 사용자의 제약 조건 변경
