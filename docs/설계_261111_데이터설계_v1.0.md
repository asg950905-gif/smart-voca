**버전**: v1.0

## 0. 데이터 저장소 개요

| 항목 | 설명 |
|------|------|
| **DBMS** | SQLite 3 (파일 기반, data/smart_voca.db) |
| **모드** | WAL (Write-Ahead Logging) — 읽기/쓰기 동시성 향상 |
| **외래키** | ON DELETE CASCADE 활성화 (PRAGMA foreign_keys = ON) |
| **인코딩** | UTF-8 |
| **동시성** | 단일 프로세스(Flask 개발 서버) 또는 다중 워커(Gunicorn)에서 각 요청이 연결을 열고 닫음 |
| **트랜잭션** | 쓰기 단위로 명시적 트랜잭션 (Database.session 컨텍스트 매니저) |

## 1. 물리 데이터베이스 스키마

### 1.1 users (사용자 계정)

**목적**: 로그인 인증, 역할 관리, 사용자별 설정 저장

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `id` | INTEGER | PK, AUTOINCREMENT | 사용자 고유 ID (FK 참조) |
| `username` | TEXT | NOT NULL, UNIQUE | 로그인 아이디 (3~20자, 영문·숫자·밑줄, 대소문자 무시) |
| `display_name` | TEXT | NOT NULL, DEFAULT '' | 표시 이름 (선택, 현재 사용 안 함) |
| `password_hash` | TEXT | NOT NULL | bcrypt 해시된 비밀번호 |
| `role` | TEXT | NOT NULL, DEFAULT 'user', CHECK | 역할: 'user' 또는 'admin' |
| `active` | INTEGER | NOT NULL, DEFAULT 1 | 활성 여부 (0=비활성, 1=활성) |
| `daily_target` | INTEGER | NOT NULL, DEFAULT 10 | **v2.0에서 이동 (user_settings로 이관 예정)** |
| `theme` | TEXT | NOT NULL, DEFAULT 'system' | **v2.0에서 이동 (user_settings로 이관 예정)** |
| `created_at` | TEXT | NOT NULL, DEFAULT NOW() | 계정 생성일시 |

**주요 제약**:
- `username` UNIQUE, COLLATE NOCASE (대소문자 무시)
- `role` CHECK (role IN ('user', 'admin'))

**인덱스**: PRIMARY KEY only

**현황**: 
- ❌ v2.0 코드에서 `users` 테이블의 `daily_target`, `theme` 컬럼은 사용되지 않음
- ✅ 대신 별도 `user_settings` 테이블 필요 (미구현)

---

### 1.2 words (단어 사전)

**목적**: 학습·시험의 단어 풀

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `id` | INTEGER | PK, AUTOINCREMENT | 단어 고유 ID (FK 참조) |
| `english` | TEXT | NOT NULL, UNIQUE COLLATE NOCASE | 영단어 (100자 이내, 중복 불가) |
| `korean` | TEXT | NOT NULL | 한글 뜻 (200자 이내) |
| `part_of_speech` | TEXT | NOT NULL, DEFAULT '' | 품사 (명사/동사/형용사 등, 선택) |
| `example` | TEXT | NOT NULL, DEFAULT '' | 예문 (선택) |
| `created_at` | TEXT | NOT NULL, DEFAULT NOW() | 추가일시 |

**주요 제약**:
- `english` UNIQUE COLLATE NOCASE (대소문자 무시로 중복 검사)

**인덱스**: PRIMARY KEY only

**관리**: 관리자가 CSV 가져오기/내보내기로 관리

### 1.3 user_word_stats (사용자별 단어 통계)

**목적**: 사용자별 단어 학습 진도 추적

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `user_id` | INTEGER | NOT NULL, FK(users.id) ON DELETE CASCADE | 사용자 |
| `word_id` | INTEGER | NOT NULL, FK(words.id) ON DELETE CASCADE | 단어 |
| `weight` | INTEGER | NOT NULL, DEFAULT 0 | 오답 가중치 (높을수록 자주 출제, 0~N) |
| `success_count` | INTEGER | NOT NULL, DEFAULT 0 | 정답 횟수 |
| `fail_count` | INTEGER | NOT NULL, DEFAULT 0 | 오답 횟수 |
| `last_studied` | TEXT | nullable | 마지막 학습 일시 |
| PK | - | (user_id, word_id) | 복합 기본키 |

**주요 제약**:
- PK: (user_id, word_id) — 사용자당 단어 1개 기록만 유지
- FK: ON DELETE CASCADE (사용자 삭제 시 모든 통계 삭제)

**인덱스**:
- PK (자동)
- user_id 기준 (학습 페이지에서 사용자별 단어 조회)

**데이터 처리**:
- `weight` 조정: 정답 → -1 (최소 0), 오답 → +1
- `success_count`, `fail_count`는 현재 사용하지 않지만 향후 "마스터 단어" 판정에 사용 가능
- 마스터 단어 조건: success_count ≥ 3 AND success_rate ≥ 80% (FR-203)

---

### 1.4 study_logs (학습 로그)

**목적**: 사용자의 일일 학습 결과 기록

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `id` | INTEGER | PK, AUTOINCREMENT | 로그 ID |
| `user_id` | INTEGER | NOT NULL, FK(users.id) ON DELETE CASCADE | 사용자 |
| `date` | TEXT | NOT NULL | 학습 날짜 (YYYY-MM-DD) |
| `words_count` | INTEGER | NOT NULL | 학습한 단어 수 (이날 푼 단어 개수) |
| `correct_count` | INTEGER | NOT NULL | 정답 단어 수 |
| `success_rate` | REAL | NOT NULL | 성공률 (correct_count / words_count × 100) |
| `duration` | INTEGER | NOT NULL, DEFAULT 0 | 소요 시간(초, 현재 미사용) |

**주요 제약**:
- FK: ON DELETE CASCADE

**인덱스**:
- `idx_study_logs_user_date`: (user_id, date)

**데이터 흐름**:
1. 사용자가 일일 학습 완료 후 결과 저장 (P10)
2. 통계 페이지에서 "최근 14일" 일별 성공률·단어 수 집계 시 활용

**현황**:
- ❌ 현재 코드에서 학습 결과를 `study_logs`에 저장하지 않고, 대신 `user_word_stats`만 업데이트
- ✅ 통계 쿼리는 `study_logs` 존재를 가정하고 있으나, 실제로는 `user_word_stats` + `study_logs` 혼용 필요

---

### 1.5 test_logs (시험 로그)

**목적**: 사용자의 시험 응시 결과 기록

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `id` | INTEGER | PK, AUTOINCREMENT | 로그 ID |
| `user_id` | INTEGER | NOT NULL, FK(users.id) ON DELETE CASCADE | 사용자 |
| `date` | TEXT | NOT NULL | 시험 응시 일시 (YYYY-MM-DD 또는 timestamp) |
| `mode` | TEXT | NOT NULL | 출제 모드 ('한→영', '영→한', '혼합') |
| `format` | TEXT | NOT NULL | 출제 형식 ('단답', '4지선다', 'OX', '빈칸', '혼합') |
| `total_problems` | INTEGER | NOT NULL | 전체 문제 수 |
| `correct_answers` | INTEGER | NOT NULL | 정답 수 |
| `score` | REAL | NOT NULL | 점수 (correct_answers / total_problems × 100) |

**주요 제약**:
- FK: ON DELETE CASCADE

**인덱스**:
- `idx_test_logs_user_date`: (user_id, date)

**데이터 흐름**:
1. 사용자가 시험 종료 시 결과 저장 (P20)
2. 통계 페이지에서 "시험 성적 추이" 차트 생성 시 활용

---

### 1.6 test_sessions (진행 중인 시험 상태)

**목적**: 서버 재시작·새로고침 후에도 시험을 이어서 풀 수 있도록 상태 저장

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `user_id` | INTEGER | PK, FK(users.id) ON DELETE CASCADE | 사용자 (사용자당 1개 시험만 진행 중) |
| `state_json` | TEXT | NOT NULL | 시험 상태를 JSON으로 직렬화<br/>- `problem_set`: 문제 배열<br/>- `current_index`: 현재 문제 번호<br/>- `score`: 현재까지 점수<br/>- `correct_count`: 정답 수 |
| `updated_at` | TEXT | NOT NULL, DEFAULT NOW() | 마지막 업데이트 일시 |

**주요 특징**:
- PK: user_id (사용자당 최대 1개 시험)
- state_json은 JSON 형식으로 저장하여 유연성 확보
- 시험 종료 시 레코드 삭제 (또는 상태 변경)

**마이그레이션 주의**:
- 시험 진행 중 새 버전 배포 시 `state_json` 구조 변경에 주의

### 1.7 app_settings (전역 설정)

**목적**: 관리자가 시스템 전역 설정 관리

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `key` | TEXT | PK | 설정 키 (예: 'max_daily_target', 'max_test_problems') |
| `value` | TEXT | NOT NULL | 설정값 (문자열로 저장, 사용시 타입 변환) |

**예시 데이터**:

| key | value | 설명 |
|-----|-------|------|
| `max_daily_target` | 50 | 최대 하루 학습량 (FR-701, FR-807) |
| `max_test_problems` | 50 | 최대 시험 문제 수 (FR-401, FR-807) |
| `total_study_days` | 200 | 전체 학습 일수 (관리자 대시보드, FR-807) |

**삽입 방식**:
- UPSERT (INSERT OR REPLACE) 사용 (database.py의 `set_setting()`)

## 4. 저장소 정책 및 주의사항

### 4.1 데이터 보관 기간

| 테이블 | 보관 기간 | 삭제 정책 |
|--------|---------|---------|
| `users` | 무제한 | 관리자가 명시적 삭제, CASCADE로 하위 데이터 삭제 |
| `words` | 무제한 | 관리자가 명시적 삭제 (사용 중인 user_word_stats는 CASCADE 삭제) |
| `user_word_stats` | 무제한 (또는 사용자 진도 초기화 시 삭제) | 사용자 삭제 또는 진도 초기화(FU-RESET-01) |
| `study_logs` | 무제한 | 사용자 삭제 또는 진도 초기화(FU-RESET-02) |
| `test_logs` | 무제한 | 사용자 삭제 또는 진도 초기화(FU-RESET-03) |
| `test_sessions` | 진행 중만 | 시험 종료 시 즉시 삭제 (타임아웃 메커니즘 없음) |

### 4.2 CASCADE 삭제 순서

사용자 삭제 시:
```
users (삭제) 
  ↓ ON DELETE CASCADE
  ├─ user_word_stats (모두 삭제)
  ├─ study_logs (모두 삭제)
  ├─ test_logs (모두 삭제)
  └─ test_sessions (삭제, 있으면)
```

단어 삭제 시:
```
words (삭제)
  ↓ ON DELETE CASCADE
  └─ user_word_stats 의 해당 단어 기록 (모두 삭제)
```

### 4.3 동시성 및 트랜잭션

**문제점**:
- SQLite는 단일 쓰기만 가능 (동시 다중 쓰기 불가)
- Gunicorn 다중 워커에서는 디드락 위험

**현행 대응**:
- Flask 개발 서버: 단일 프로세스, 문제 없음
- 프로덕션(Gunicorn): WAL 모드로 읽기/쓰기 동시성 향상, 타임아웃 설정 (timeout=10초)

**향후 개선**:
- PostgreSQL/MySQL로 마이그레이션 (다중 쓰기 지원)
- 또는 Redis 기반 세션 저장소 추가 (로그인 시도 제한)

### 4.4 데이터 무결성

**외래키**:
- 모든 FK는 ON DELETE CASCADE 설정
- PRAGMA foreign_keys = ON 연결마다 실행

**기본값**:
- `active`, `role`, `weight` 등 NOT NULL 필드는 기본값 설정
- 없으면 INSERT 시 명시적으로 값 제공 필요

**제약 검증**:
- `username` UNIQUE COLLATE NOCASE: 대소문자 무시 중복 검사
- `role` CHECK (role IN ('user', 'admin')): 값 검증은 DB 레벨 + 애플리케이션 레벨

## 5. 마이그레이션 및 스키마 변경 전략

### 5.1 현황

- **마이그레이션 도구**: 없음 (SQLAlchemy/Alembic 미사용)
- **스키마 변경 방식**: `CREATE TABLE IF NOT EXISTS` (기존 테이블은 변경 안 함)

### 5.2 컬럼 추가/삭제 시 절차

1. **개발 환경**: `python ai-agent/scripts/시연데이터생성.py --reset` 으로 DB 재생성
2. **프로덕션**: 별도 스크립트 작성 필요
   - 예: ALTER TABLE, 데이터 마이그레이션, 검증

### 5.3 식별된 마이그레이션 필요 항목

| 항목 | 현황 | 필요 조치 |
|------|------|---------|
| `users.daily_target`, `users.theme` | 사용되지 않음 | `user_settings` 테이블 분리 (v2.1+) |

| `test_sessions.state_json` 구조 변경 | 가능성 높음 | 새 필드 추가시 기존 데이터 호환성 확인 필요 |

## 6. 인덱싱 전략

### 6.1 현행 인덱스

| 인덱스명 | 테이블 | 컬럼 | 용도 |

- `test_logs.date` — 통계 날짜 범위 조회

## 7. 데이터 보안 및 격리

### 7.1 사용자 데이터 격리

**원칙**: 모든 쿼리에 `WHERE user_id = ?` 조건 추가

**예**:
```sql
-- ❌ 위험
SELECT * FROM study_logs WHERE date = '2026-11-11';

-- ✅ 안전
SELECT * FROM study_logs WHERE user_id = ? AND date = '2026-11-11';
```

**관리자**: 모든 데이터 조회 가능 (권한 검사는 애플리케이션 레벨)

### 7.2 민감 정보

- **비밀번호**: bcrypt 해시로 저장 (복호화 불가)
- **세션**: Flask 세션(서버 메모리 또는 쿠키 서명)

## 부록: SQL 스키마 (현행)

```sql
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;

CREATE TABLE IF NOT EXISTS users (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    username      TEXT    NOT NULL UNIQUE,
    display_name  TEXT    NOT NULL DEFAULT '',
    password_hash TEXT    NOT NULL,
    role          TEXT    NOT NULL DEFAULT 'user' CHECK (role IN ('user', 'admin')),
    active        INTEGER NOT NULL DEFAULT 1,
    daily_target  INTEGER NOT NULL DEFAULT 10,
    theme         TEXT    NOT NULL DEFAULT 'system',
    created_at    TEXT    NOT NULL DEFAULT (datetime('now', 'localtime'))
);

CREATE TABLE IF NOT EXISTS words (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    english        TEXT NOT NULL UNIQUE COLLATE NOCASE,
    korean         TEXT NOT NULL,
    part_of_speech TEXT NOT NULL DEFAULT '',
    example        TEXT NOT NULL DEFAULT '',
    created_at     TEXT NOT NULL DEFAULT (datetime('now', 'localtime'))
);

CREATE TABLE IF NOT EXISTS user_word_stats (
    user_id       INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    word_id       INTEGER NOT NULL REFERENCES words(id) ON DELETE CASCADE,
    weight        INTEGER NOT NULL DEFAULT 0,
    success_count INTEGER NOT NULL DEFAULT 0,
    fail_count    INTEGER NOT NULL DEFAULT 0,
    last_studied  TEXT,
    PRIMARY KEY (user_id, word_id)
);

CREATE TABLE IF NOT EXISTS study_logs (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id       INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    date          TEXT    NOT NULL,
    words_count   INTEGER NOT NULL,
    correct_count INTEGER NOT NULL,
    success_rate  REAL    NOT NULL,
    duration      INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE IF NOT EXISTS test_logs (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id         INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    date            TEXT    NOT NULL,
    mode            TEXT    NOT NULL,
    format          TEXT    NOT NULL,
    total_problems  INTEGER NOT NULL,
    correct_answers INTEGER NOT NULL,
    score           REAL    NOT NULL
);

CREATE TABLE IF NOT EXISTS test_sessions (
    user_id    INTEGER PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
    state_json TEXT NOT NULL,
    updated_at TEXT NOT NULL DEFAULT (datetime('now', 'localtime'))
);

CREATE TABLE IF NOT EXISTS app_settings (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_study_logs_user_date ON study_logs(user_id, date);
CREATE INDEX IF NOT EXISTS idx_test_logs_user_date  ON test_logs(user_id, date);
```
