## 2. 비즈니스 요구사항 (BRD)

### 2.1 배경 및 목표

**배경**
- 영어 단어 학습의 반복성, 지루함, 성과 추적의 어려움이 학습자의 포기율을 높임
- 게임화와 시각적 피드백을 통해 학습 동기를 유지할 필요가 있음

**비즈니스 목표**
1. 사용자가 **매일 꾸준히 학습할 수 있는 환경** 제공 (연속 학습일, 일일 목표)
2. **학습 성과를 가시화** (대시보드, 통계, 차트, 주간 리그)
3. **개인화된 학습 경로** 제공 (오답 우선 출제, 약점 분석)

## 3. 시스템 범위 (SS)

### 3.1 기능 범위 — 포함 (In Scope)

#### 3.1.1 사용자 인증 및 관리
- 회원가입/로그인 (아이디·비밀번호, 세션 기반)
- 로그인 시도 제한 (5회 실패 시 5분 잠금)
- 계정 활성화/비활성화 (관리자)

#### 3.1.2 랜딩 페이지 및 대시보드
- 비로그인: 랜딩 페이지 (DB 실제 수치 표시)
- 로그인: 개인 대시보드 (학습 진도, XP, 레벨, 연속 학습일 등)

#### 3.1.3 학습 기능
- 일일 단어 제시 (하루 목표 개수)
- 우선순위: 오답 가중치 → 미학습 → 오래된 단어 → 무작위
- 단어별 학습 완료/미완료 선택
- 한 번에 결과 저장

#### 3.1.4 시험 기능
- 시험 설정 (문제 수, 모드: 한→영/영→한/혼합, 형식: 단답/4지선다/OX/빈칸/혼합)
- 오답 우선 출제
- 한 문제씩 제시, 즉시 채점 (공백·대소문자 무시)
- 시험 진행 상태 DB 저장 (새로고침·재시작 후에도 이어짐)
- 시험 완료 시 점수·상세·XP 제공

#### 3.1.5 통계 및 리포팅
- 요약 통계 (학습일수, 누적 단어, 성공률, 시험 점수 등)
- 차트 (최근 14일: 학습률, 단어 수, 시험 점수, 약점 단어)
- CSV 내보내기 (UTF-8 BOM)

#### 3.1.6 게임화 및 리그
- XP 획득 규칙 (학습 정답 +10, 오답 +2, 시험 정답 +15, 오답 +3)
- 레벨 시스템 (누적 XP 기반)
- 주간 리그 (최근 7일 XP 순위, 상위 20명 + 본인)

#### 3.1.7 사용자 설정
- 일일 학습량 설정 (1~50, 관리자 설정)
- 테마 선택 (System/Light/Dark)
- 학습 기록 초기화 (단어 통계, 로그, 진행 중 시험)

#### 3.1.8 관리자 기능
- 단어 관리 (CRUD, 일괄 가져오기)
- 사용자 관리 (조회, 활성화/비활성화, 초기화)
- 전역 설정 (일일 최대 목표, 최대 시험 문제 수 등)
- 전체 통계 조회

## 6. 제약사항 및 가정

### 6.1 기술 제약
- SQLite 는 단일 파일 DB 라 동시 다중 쓰기에 제한 있음 (현재 로컬 학습용이므로 허용)
- 프로토타입 단계이므로 대규모 동시 사용자 미지원
- 프로덕션 배포는 Gunicorn + Nginx 필요 (현재 Flask 개발 서버)

### 6.2 운영 제약
- PUBLIC GitHub 저장소이므로 비밀정보(API 키, DB) 절대 커밋 금지
- `.gitignore` 로 `data/`, `.env`, `__pycache__/` 제외
- 개인정보(학번, 실명) 익명화 필수

### 6.3 가정
- 학습자는 주로 개인 PC에서 접속 (Windows 11 기준 테스트)
- 하루 최대 학습량은 50개 단어 (관리자 설정)
- 시험은 서버에서 진행·채점 (클라이언트 부정행위 방지)
