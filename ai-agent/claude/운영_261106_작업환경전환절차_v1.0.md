## 작업 시작 시
1. `git status` 로 깨끗한지 확인 후 `git pull` 을 먼저 한다.
   깨끗하지 않으면 `git fetch` → `git diff HEAD origin/master --stat` 으로 원격 변경과 로컬 변경이
   겹치는 파일이 있는지 본다. 겹치지 않으면 `git pull --ff-only`, 겹치면 사용자에게 어느 쪽을 살릴지 묻는다.
2. 가장 최근 `ai-agent/claude/일지_*.md` 의 "다음 할 일"을 읽고 이어서 작업한다.
3. 처음 쓰는 환경이면 가상환경 생성 후 `pip install -r requirements.txt` 가 되는지 확인한다.

## 작업 종료 시
1. 일지(`ai-agent/claude/일지_yymmdd_*.md`)에 **한 일 / 다음 할 일 / 주의점**을 남긴다.
   테스트로 띄운 서버(포트 5000)가 남아 있으면 종료한다 (Claude 가 직접 띄운 프로세스 한 개만, 포트 기준으로).
2. 사용자 승인 후 커밋하고 `git push` 까지 한다. 푸시하지 않은 작업은 다른 환경에서 볼 수 없다.

## 환경별 동기화되지 않는 것
- `.env`, `data/` 는 git 에 없다. 필요하면 USB·개인 클라우드 등으로 따로 옮긴다.
  실습실 PC 의 개인 프로필 안에는 남겨도 되지만, 실사용 데이터(개인정보)는 두지 않는다.
- Claude 자동 메모리(`~/.claude/...`)는 계정·PC 별로 따로이므로, 지켜야 할 규칙은 CLAUDE.md 에 적는다.

## 학교 실습실 보안 체크리스트 (공용 PC)
실습실 PC 는 **개인 Microsoft 계정으로 Windows 로그인**한다. 사용자 프로필(`C:\Users\<계정>`)이 학생별로 분리되므로
git 전역 설정(`.gitconfig`)과 `gh` 로그인 토큰(자격 증명 관리자)은 다른 학생 계정에서 보이지 않는다.

- 프로젝트는 교수님 지정 경로(`문서\dev\smart-voca`)에 두고 계속 사용한다.
- git `--global` 사용자 설정과 `gh` 로그인은 유지해도 된다.
  작업 시작 시 `git config user.email` 로 커밋 작성자가 본인인지 확인한다.
- **자리를 뜰 때는 Windows 로그아웃**한다 (잠깐 비울 때는 `Win+L` 잠금). 로그인 상태로 두면 누구나 GitHub 에 접근할 수 있다.
- 학기 종료 등 이 PC 를 더 쓰지 않게 되면 `gh auth logout`, 자격 증명 관리자의 `github.com` 항목을 삭제한다.
- 공용 계정(공유 로그인)으로 쓰게 되면 위 완화는 적용하지 않는다: `--local` 설정만 쓰고 종료 전 `gh auth logout`.
- 토큰·비밀번호·`.env` 내용을 대화창에 붙여넣지 않는다. 교수님 계정의 사용 범위는 교수님 방침을 따른다.
- 저장소가 PUBLIC 이므로 학번·실명·키가 커밋에 들어가지 않게 한다.
