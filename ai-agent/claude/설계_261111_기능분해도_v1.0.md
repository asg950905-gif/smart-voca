## 0. 분해 원칙

1. **계층 정의**
   - **L0**: 시스템 전체
   - **L1**: 기능 영역 (프로세스 카테고리)
   - **L2**: 기능군 (프로세스 내 단계)
   - **L3**: 원자 기능 (더 이상 분해 불가)

2. **명명 규칙**
   - 코드화: `FN-{영역코드}-{기능코드}` (예: `FN-AUTH-101`)
   - 이름: "~하다" 동사형 사용

3. **추적성**
   - 각 L3 기능은 프로세스(P**), 요구사항(FR/NFR)과 연결
   - 구현 담당 모듈 명시

## 2. 기능별 상세 정의

### 인증 및 계정 관리 (FA-***)

| 기능 코드 | L3 기능명 | 프로세스 | 요구사항 | 입력 | 처리 로직 | 출력 | 구현 모듈 |
|---------|---------|--------|--------|------|---------|------|---------|
| FA-REG-01 | 아이디 유효성 검증 | P01 | FR-101 | `username` | 정규식: `[a-zA-Z0-9_]{3,20}` | 유효 여부 | `auth_manager.py` |
| FA-REG-02 | 비밀번호 유효성 검증 | P01 | FR-101 | `password` | 길이 ≥ 6, 개수 확인 | 유효 여부 | `auth_manager.py` |
| FA-REG-03 | 중복 아이디 확인 | P01 | FR-101 | `username` | DB SELECT (대소문자 무시) | 중복 여부 | `auth_manager.py` |
| FA-REG-04 | 비밀번호 해시 및 저장 | P01 | FR-101 | `password` | bcrypt 해시, DB INSERT | user_id | `auth_manager.py`, `database.py` |
| FA-REG-05 | 사용자 초기 데이터 생성 | P01 | FR-101 | user_id | user_settings 기본값 생성 | 완료 신호 | `settings_manager.py` |
| FA-LOGIN-01 | CSRF 토큰 검증 | P02 | NFR-001 | token | 세션 토큰과 비교 | 검증 결과 | `security.py` |
| FA-LOGIN-02 | 로그인 시도 제한 확인 | P02 | FR-104 | IP, username | 메모리: 5분 내 5회 초과 | 차단 여부 | `security.py` |
| FA-LOGIN-03 | 사용자 존재 여부 확인 | P02 | FR-105 | username | DB SELECT | 사용자 레코드 또는 NULL | `auth_manager.py` |
| FA-LOGIN-04 | 계정 활성 상태 확인 | P02 | FR-106 | user | is_active=1, deleted_at 확인 | 활성 여부 | `auth_manager.py` |
| FA-LOGIN-05 | 비밀번호 검증 | P02 | FR-102 | password, hash | bcrypt_verify() | 일치 여부 | `auth_manager.py` |
| FA-LOGIN-06 | 세션 생성 및 쿠키 설정 | P02 | NFR-002 | user, role | 새 세션 시작, HttpOnly 쿠키 | 세션 ID | `auth_routes.py` |
| FA-LOGIN-07 | 역할별 리다이렉트 | P02 | FR-102 | role, next_url | 경로 검증 후 리다이렉트 | HTTP 302 | `auth_routes.py` |
| FA-LOGOUT-01 | 세션 무효화 | P02 | FR-103 | session_id | 세션 저장소 삭제 | 완료 신호 | `auth_routes.py` |
