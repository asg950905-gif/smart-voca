## 받은 요구·결정 (맥락 유지용)

- **피드백 1** 학습 화면에서 카드가 바뀔 때 발음이 자동 재생돼 놀람 → 자동 재생 제거, 발음 버튼·P 키로만 재생. 설정에 "카드 넘길 때 자동 발음" 스위치(기본 꺼짐)를 두어 켠 사람만 자동 재생.
- **피드백 2** 시험이 전체 단어(2,283개)에서 출제돼 처음 보는 단어가 나옴 → 시험 시작 화면에 출제 범위 선택. 사용자가 확정한 문구: ① **오늘 공부한 단어**(기본) ② **지금까지 공부한 단어** ③ **전체 단어**. ①②에는 **"학습·시험에서 본 단어 기준"** 작은 안내를 붙인다(시험에서 본 단어도 포함되기 때문).
  - ①②는 `user_word_stats` 기준, 틀린 단어(weight 높은 순) 우선. 범위가 비면 "먼저 학습을 해주세요", 문제 수보다 적으면 있는 만큼만 출제. 4지선다 오답 보기는 전체 단어에서(같은 뜻 제외 규칙 유지).
- **동의어 채점** 한→영 단답에서 뜻이 같은 영어 단어를 쓰면 정답 처리하고 "정답 처리 (출제 단어: obvious)"로 보여 준다.
- 사용자 승인(기본안): ① 자동 발음 설정은 **계정(DB 컬럼)에 저장**, ② "학습한 단어"는 **`user_word_stats` 기록이 있는 단어**(시험에서 본 단어 포함), ③ API 의 `scope` 생략 시 **`all`**(기존 호출 호환), ④ **docs/ 는 이번에 고치지 않고** 이 일지 "다음 할 일"에 기록(배포 문서 작업 때 한 번에).
- 후속 결정(사용자, 같은 날 저녁): **③ 전체 단어는 틀린 단어 우선 없이 무작위**로 바꾼다(②는 그대로 틀린 단어 우선). 서버는 `127.0.0.1` 로 재시작(실DB 백업 먼저). `app.py` import 부작용은 **다음 배포 작업에서 `wsgi.py` 를 분리할 때 함께** 고친다.
- 푸시: 사용자가 확인한 뒤 `2d43a23`(③ 무작위 수정)까지 푸시했다. 이 일지를 고친 커밋은 푸시 전.

## 결정 기록 (ADR)

### ADR-A: 자동 발음 설정을 계정(DB)에 저장하고, 마이그레이션 코드를 처음 도입
- **배경**: 설정 화면의 개인 설정(하루 학습량·테마)은 `users` 컬럼에 저장한다. 그런데 `SCHEMA` 는 `CREATE TABLE IF NOT EXISTS` 라 이미 만들어진 DB 의 컬럼이 바뀌지 않는다(CLAUDE.md 주의사항).
- **대안**: (1) 브라우저 `localStorage` — DB 변경이 없지만 기기마다 따로 설정. (2) 계정 컬럼 + 수동 SQL. (3) 계정 컬럼 + 앱이 시작할 때 자동 마이그레이션.
- **결정**: (3). `database.MIGRATIONS` 목록에 (테이블, 컬럼, 정의)를 적으면 `init_schema` 가 없을 때만 `ALTER TABLE` 하고, 변경 직전 같은 폴더(`data/`, git 제외)에 `smart_voca_migration_<시각>.db` 백업을 만든다.
- **결과**: 새 DB 와 옛 DB 모두 같은 코드로 열린다. 기본값 0(꺼짐)이라 기존 계정은 동작이 바뀌지 않는다. 앞으로 컬럼을 더 추가할 때도 이 목록에 한 줄 추가하면 된다.

### ADR-B: "학습한 단어"의 기준은 `user_word_stats`(학습·시험에서 본 단어)
- **배경**: `last_studied` 는 학습 화면뿐 아니라 시험 종료 때도 갱신된다. 학습 화면에서만 본 단어를 구분하려면 컬럼이 더 필요하다.
- **대안**: (1) 기록이 있는 단어 기준(스키마 변경 없음). (2) 학습 화면에서만 갱신되는 컬럼 추가(엄격).
- **결정**: (1). 대신 화면에 "학습·시험에서 본 단어 기준" 안내를 붙였다.
- **결과**: ③ 전체 단어 시험을 본 뒤에는 그 단어들이 ①②에 들어온다(테스트 `test_words_seen_in_a_test_count_as_studied_words` 로 고정). 엄격하게 구분하고 싶으면 컬럼 추가가 필요하다.

### ADR-C: 한→영 단답에서 동의어를 정답으로 인정
- **배경**: 단어 검수에서 뜻이 같은 동의어 쌍(evident/obvious 등)을 두기로 했다. 한→영 단답에서는 둘 중 하나만 정답이라 억울한 오답이 생긴다.
- **결정**: 입력한 영단어가 DB 에 있고 그 뜻이 출제 단어의 뜻과 normalize 기준으로 같으면 정답. 한→영·단답형에서만 적용(4지선다·OX·빈칸형은 보기가 정해져 있고, 영→한은 한글 답만 비교). 통계·XP 는 **출제된 단어** 기준으로 반영하고 입력한 동의어의 통계는 올리지 않는다.
- **결과**: 응답에 `synonym`(사용자가 쓴 단어)이 들어가고 화면은 "정답 처리 (출제 단어: …)"를 보여 준다. 단어가 DB 에 없거나 뜻이 다르면 오답.

### ADR-D: ③ 전체 단어는 무작위 출제 (틀린 단어 우선은 ①②만)
- **배경**: 브라우저 점검 중, 오답이 쌓인 사용자가 ③ 전체 단어 시험을 보면 문제가 그 오답 단어들로만 채워지는 것을 확인했다(기존 규칙: weight 높은 순).
- **대안**: (1) 기존대로 weight 우선. (2) ③ 만 무작위. (3) ③ 에도 weight 를 일부만 반영.
- **결정**: (2). 틀린 단어 복습은 ② 가 맡는다.
- **결과**: `scope` 가 `all` 이거나 생략된 호출은 모두 학습 기록과 무관한 무작위 출제가 된다(이전에는 생략 시에도 weight 우선). 회귀 테스트로 고정했다.

## 주의점

- 서버는 11/13 20:16경 **`127.0.0.1` 로 재시작**했다(PID 27120). 재시작 전에 `backups/smart_voca_261113_201556_서버재시작전.db` 로 실DB 를 백업했고(건수·무결성 확인), 새 기능과 ③ 무작위가 반영돼 있다(설정·범위 API, 시험·설정 화면으로 확인).
- **실DB 가 이미 마이그레이션됐다.** `app.py:143` 의 `app = create_app()` 때문에 테스트가 `from app import ...` 만 해도 기본 경로의 실DB 를 연다. 11/13 15:42 에 첫 pytest 실행이 `users.auto_speak` 를 추가했고, 변경 전 백업(`data/smart_voca_migration_261113_154251.db`)이 만들어졌다. 건수(users 10, words 2,283, study_logs 56, test_logs 32)와 무결성은 그대로, 계정의 `auto_speak` 는 모두 0. 옛 코드 서버는 추가 컬럼에 영향받지 않는다(응답 200 확인). 앞으로 스키마를 바꾸는 작업은 "pytest 만 돌려도 실DB 가 바뀐다"는 점을 먼저 알린다.
- 시험 시작 화면의 기본 범위가 ① 이라, **학습을 한 적 없는 사용자는 기본 선택으로는 시험을 시작할 수 없다**(안내와 "학습하러 가기" 링크가 나온다). ③ 전체 단어로 바꾸면 시작할 수 있다.
- ③ 전체 단어는 **틀린 단어 우선 없이 무작위**다(ADR-D). 틀린 단어를 먼저 복습하려면 ② 를 쓴다. `scope` 를 생략한 API 호출도 무작위다.
- 브라우저 점검 스크립트를 여러 번 돌리는 동안 **한 번은 ② 시험 구간에서 문제 대기 시간 초과**로 실패했고, 바로 다시 돌리면 통과했다. 원인은 확인하지 못했다(스크립트의 타이밍으로 추정). 앱 오류는 확인되지 않았다.
- 자동 발음을 켜도 **페이지에 들어온 직후 첫 카드는** 브라우저 정책(사용자 조작 전 음성 제한)으로 안 들릴 수 있다. 두 번째 카드부터 보장된다. 점검은 `speechSynthesis.speak` 호출 횟수로 했고 실제 소리는 듣지 못했다.
- 동의어 정답 처리는 한→영 단답에만 적용된다.
