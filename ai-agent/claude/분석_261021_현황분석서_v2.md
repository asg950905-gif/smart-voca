## 1. 기존 비즈니스 프로세스

### 1.1 v1.0 (CLI) 사용 흐름
```
CLI 프로그램 실행
  ↓
메뉴 선택 (텍스트 기반)
  ↓
입력 및 처리
  ↓
결과 텍스트 출력
```

### 1.2 v1.0의 문제점
| 문제 | 영향 |
|------|------|
| **텍스트 기반 UI** | 사용성 낮음, 직관적이지 않음 |
| **메뉴 네비게이션** | 깊은 단계, 번호 입력 반복 |
| **시각적 피드백 부족** | 진도 상태 한눈에 파악 어려움 |
| **시험 중 불편** | 선택지를 텍스트로만 표시 |
| **보고서 텍스트만** | 그래프/차트 없음 |

---

## 2. PyQt6 GUI 전환의 필요성

### 2.1 개선 효과

| 영역 | CLI (v1.0) | GUI (v2.0) |
|------|-----------|----------|
| **UI/UX** | 텍스트만 | 그래픽 요소 |
| **학습 동기** | 낮음 | 높음 |
| **진도 시각화** | 없음 | 프로그레스 바 |
| **시험 경험** | 불편 | 쾌적함 |
| **보고서** | 텍스트 | 차트 포함 |

### 2.2 GUI의 장점
```
✓ 직관적인 인터페이스
✓ 한번에 여러 정보 표시
✓ 클릭으로 쉬운 네비게이션
✓ 실시간 진도율 시각화
✓ 시험 중 선택지 버튼 클릭
✓ 그래프로 학습 통계 표시
✓ 드래그&드롭으로 파일 관리
✓ 토스트 메시지로 빠른 피드백
```

## 3. PyQt6 선택 이유

### 3.1 PyQt6 vs PyQt5 비교

| 항목 | PyQt5 | PyQt6 |
|------|-------|-------|
| **안정성** | 매우 높음 | 높음 |
| **기능** | 풍부 | 더 풍부 |
| **성능** | 우수 | 더 우수 |
| **레이아웃** | 기본 | 개선됨 |
| **다크모드** | 지원 | 내장 지원 |
| **개발 편의** | 좋음 | 더 좋음 |
| **커뮤니티** | 매우 큼 | 커지는 중 |

**선택 이유**: v2.0은 최신 기술을 활용하여 현대적이고 유지보수하기 좋은 프로그램을 만들기 위해 PyQt6 선택

## 4. 사용자 기대

### 4.1 v1.0 사용자 피드백 예상
```
"CLI가 너무 불편해요"
"진도를 한눈에 보고 싶어요"
"아름다운 UI로 만들어줄 수 없을까요?"
"시험할 때 선택지가 버튼으로 있으면 좋겠어요"
```

### 4.2 v2.0 기대 기능
| 기대 | 구현 |
|------|------|
| **메인 대시보드** | 학습 진도, 오늘 학습 상태 한눈에 |
| **직관적 네비게이션** | 탭 또는 사이드바로 기능 분류 |
| **시각적 진도** | 프로그레스 바, 완료율 퍼센트 |
| **시험 UI** | 선택지 버튼, 문제 순서 표시 |
| **학습 통계** | 그래프, 차트로 성과 시각화 |
| **설정 패널** | 일일 목표, 테마 등 직관적 설정 |

## 6. 기술 스택 비교 (v1.0 vs v2.0)

### v1.0 (CLI)
```
CLI (argparse) → Business Logic → CSV/JSON File
```

### v2.0 (PyQt6 GUI)
```
PyQt6 GUI (Widgets) → Business Logic → CSV/JSON File
  ├─ Main Window
  ├─ Dialogs
  ├─ Widgets (레이아웃, 버튼, 입력창)
  └─ Signal/Slot (이벤트 처리)
```

## 7. 개발 전략

### 7.1 점진적 개발
```
Phase 1: 기본 구조 (Window, 레이아웃, 기본 버튼)
Phase 2: 각 기능 모듈 (암기, 시험, 보고서)
Phase 3: UI/UX 개선 (스타일, 아이콘, 애니메이션)
Phase 4: 최적화 및 테스트
```

### 7.2 v1.0 코드 재사용
```
✓ Business Logic 재사용 (word_manager, study_manager 등)
✓ 데이터 포맷 동일 (CSV, JSON)
✓ 알고리즘 그대로 사용 (가중치 계산 등)
✓ 오직 UI만 변경 (CLI → PyQt6 GUI)
```
