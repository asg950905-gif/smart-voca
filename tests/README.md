# tests — 자동 테스트

**파일 위치**: `tests/README.md`
**작성일**: 2026-11-02
**버전**: v1.0
**설명**: pytest + Flask 테스트 클라이언트로 전 경로를 검증한다 (22개).

## 실행
```powershell
pip install -r requirements-dev.txt
python -m pytest tests -q
```

## 무엇을 검증하나 (`test_backend.py`)
| 분류 | 검증 내용 |
| :--- | :--- |
| 인증·권한 | 비로그인 차단, 가입 검증, **가입 시 관리자 권한 지정 불가**, 비활성 계정 로그인 불가, 5회 실패 잠금, 오픈 리다이렉트 차단 |
| CSRF | 토큰 없는 POST 는 400 |
| 관리자 | 일반 사용자의 관리자 화면·API 차단(403), 단어 CRUD·중복, CSV 가져오기(건너뜀·오류), 사용자 관리 보호장치(자기 자신 변경 금지) |
| 학습·시험 | 학습 기록·진도·연속일, 오답 단어 우선 출제, 시험 전 과정, **시험 중 정답이 클라이언트에 노출되지 않음** |
| 데이터 격리 | **사용자 A 의 기록이 B 에게 보이지 않음**, 동시 시험 진행 |
| 화면 | 사용자·관리자 모든 페이지가 200, 권한 없는 사용자의 403 화면에 관리자 메뉴 미노출(회귀 테스트) |

## 설계 이유
- **테스트마다 임시 DB** (`tmp_path` + `create_app`) → 테스트끼리, 그리고 실제 `data/` 와 서로 영향을 주지 않는다.
- **로그인 헬퍼가 CSRF 토큰을 다시 심는 이유**: 로그인은 세션을 새로 만들어 토큰이 사라진다. 실제 브라우저는 이동한 페이지를 렌더링하며 새 토큰을 받으므로 같은 상황을 재현한다.
- 버그를 고칠 때는 **회귀 테스트를 먼저/함께 추가**한다 (예: 403 화면 메뉴 노출, 비활성화 안내).

## 테스트로 확인하지 못하는 것
- 브라우저 JS 동작과 레이아웃은 pytest 로 검증되지 않는다. 대신 Playwright(Edge)로 사용자·관리자·모바일·다크모드 흐름을 수동 리허설했다 (`ai-agent/claude/테스트_261102_시연 시나리오 v1.0.md`).
- 부하(동시 접속 수십 명) 테스트는 하지 않았다.
